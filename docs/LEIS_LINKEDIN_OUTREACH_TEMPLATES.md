# LEIS LinkedIn Outreach Templates

Purpose: short, human, non-spam LinkedIn messages for sharing the LEIS package with AI researchers, Google / DeepMind leaders, Discovery Loop, and developer relations people.

Tone rule: peer-to-peer, intellectually humble, no hype, no claim that LEIS “solves AGI” or guarantees truth. Ask for criticism, not endorsement.

## Template A — Connection request, under 300 characters

Hi [Name], I’m building LEIS: an open, stateless validation loop above LLMs for reality markers, context drift and continuation. Your work on AI loops/safety made me think you might find the protocol worth a glance. Would love to connect. — Martin

Character count: 290 including spaces, depending on LinkedIn dash rendering.

## Template B — Short private note after connection

Hi [Name],

Thanks for connecting. I’ll keep this short.

I’m building LEIS — Reality-Oriented Understanding — as an open protocol layer above LLMs. The idea is not to replace Gemini/OpenAI/local models, but to give generated claims a small, auditable validation loop before they become trusted context.

The current package includes a whitepaper, public Root Seed files, and a Python middleware proof-of-concept that checks LLM output against explicit Reality Markers and routes drift into a Conflict Capsule.

Live hub: https://leis-understanding-system.puzik.chatgpt.site/
GitHub: https://github.com/MartinPuzik/LEIS-WEB

I would be grateful for technical criticism — especially where the protocol is too weak, too vague, or missing a serious validation boundary.

Warmly,
Martin Pužík

## Template D — More technical follow-up

Hi [Name],

One extra technical note on LEIS:

The core equation is not meant as a claim that truth can be mathematically forced from an LLM. It is narrower: a state-machine invariant for keeping generated claims inside a loop of observation, activation, recognition, validation, adaptation, lineage and reconstruction.

In practice, the middleware treats the LLM as a predictive engine and LEIS as an external validation boundary. If an assertion conflicts with active Reality Markers, it is quarantined rather than silently promoted into usable context.

That is the part I would most like challenged.

GitHub: https://github.com/MartinPuzik/LEIS-WEB
Whitepaper: https://github.com/MartinPuzik/LEIS-WEB/blob/main/docs/leis-architecture-whitepaper.pdf

Martin

## Do not use

Avoid:

- “AI revolution” as the first phrase.
- “zero hallucination future”.
- “mathematical proof of truth”.
- “Google needs this”.
- attaching too many files before they ask.

Better:

- “open protocol proposal”.
- “proof-of-concept”.
- “validation boundary”.
- “technical criticism welcome”.
- “prediction is not the same as validated reality”.
